## Why a mock server?

AgentCore's OBO exchange needs a token endpoint that accepts a client-credentials +
assertion grant and returns a user-scoped token. In production this would be your
corporate IdP (e.g. Amazon Cognito, Okta, Entra ID, Auth0). For the workshop we deploy a minimal Lambda ("the mock server")
that does the same thing with zero external dependencies.

The mock server:

- Exposes `/.well-known/openid-configuration` (OIDC discovery)
- Exposes `/token` (accepts `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`)
- Validates basic auth credentials (client ID + secret)
- Copies the `sub` claim from the inbound assertion into the new token
- Signs the output token with a workshop RSA key
- Serves JWKS at `/jwks.json` (bundled from the keypair generated by `keygen.sh`)

## Confirm the mock server is available

The mock server was deployed during [Step 3 of the foundation](../../30-deploy-foundation/). Confirm that `MOCK_SERVER_URL` is still set:

```bash
echo $MOCK_SERVER_URL
```

You should see a URL like `https://<api-id>.execute-api.us-east-1.amazonaws.com`. If the variable is empty (e.g. after a CloudShell timeout), re-deploy and re-set it:

```bash
cd ~/agentic-runtime-security-on-aws-agentcore/applications/oauth-mock-server
bash deploy.sh

MOCK_SERVER_URL="https://$(aws apigatewayv2 get-apis \
  --query "Items[?Name=='oauth-mock-api'].ApiId | [0]" \
  --output text).execute-api.${AWS_REGION:-us-east-1}.amazonaws.com"
```

The deploy script creates the mock server Lambda and places an API Gateway HTTP API in front of it as a public endpoint. The `MOCK_SERVER_URL` variable is used throughout UC2 — AgentCore Identity calls it during the OBO token exchange, and you'll reference it when registering the credential provider in the next step.

## Verify

```bash
curl -s "$MOCK_SERVER_URL/.well-known/openid-configuration" | python3 -m json.tool
```

Expected output includes `token_endpoint`, `jwks_uri`, and `authorization_endpoint`
all pointing at your API Gateway URL.

```bash
curl -s "$MOCK_SERVER_URL/jwks.json" | python3 -m json.tool
```

Confirm you see at least one RSA key with `use: sig`.

## What this gives you

A standards-compliant OIDC token endpoint that AgentCore Identity can call during
the OBO exchange. The signed tokens it issues will be presented to Vault in the next
steps.
